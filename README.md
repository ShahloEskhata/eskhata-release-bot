# Eskhata Release Bot

Бот для групп тестирования релизов (например, «Release Testing Tasks»): разбирает список релиза, раздаёт задачи тестировщикам
(в личку, если они писали боту `/start`, иначе в группу), собирает подтверждения со скриншотами/видео, напоминает,
готовит итоговый отчёт и объявляет командам, что сервер переключен.

## Запуск

1. В Telegram: @BotFather → `/newbot` → скопировать токен.
2. Добавить бота в группу (желательно дать право закреплять сообщения — для `/guide`).
3. `copy .env.example .env` и вписать `BOT_TOKEN`.
4. `npm install`, затем `npm start`.
5. В группе написать `/myid` — получите свой user id и id чата; впишите их в `.env`
   (`ADMIN_IDS`, `ALLOWED_CHAT_ID`) и перезапустите бота.
   Ещё одного админа можно добавить в `ADMIN_USERNAMES` (username без `@`, через запятую) или его ID в `ADMIN_IDS`.
   Админ запускает `/release` и остальные команды, а также может нажимать кнопки по любой задаче.
   Админы задаются один раз и действуют во всех группах из `ALLOWED_CHAT_ID`. Каждому админу и каждому тестировщику
   стоит один раз написать боту `/start` в личные сообщения (иначе личные уведомления придут в группу).
   Боту в каждой группе лучше дать права **администратора** (хотя бы «Закреплять сообщения»): у обычного участника
   при включённом privacy mode Telegram доставляет не все команды.
6. Выполнить `/guide` — бот пришлёт и закрепит памятку для QA.

### Чтобы бот работал всегда

Бот должен работать на постоянно включённой машине: пока он выключен, кнопки не работают и напоминаний нет.

**Сервер (лучший вариант).** Скопируйте папку на сервер, создайте `.env` и выполните:
```
docker compose up -d --build
```
Контейнер сам поднимается после падения и перезагрузки сервера. Состояние и копии лежат в `./data`,
`testers.json` правится прямо на сервере (затем `/reload` в группе).

**Что передать девопсу:** папку бота (без `node_modules`), заполненный `.env` (токен, `ADMIN_IDS`, `ALLOWED_CHAT_ID`, `TZ_NAME` и др. — см. `.env.example`) и `testers.json`. Нужен Docker с доступом в интернет к `api.telegram.org`. Перед переездом остановите бота на своём компьютере: два экземпляра с одним токеном конфликтуют (ошибка 409). Чтобы сохранить текущие релизы и статистику, перенесите папку `data/`. После запуска проверьте `docker compose logs -f release-bot` и выполните `/status` в группе.

**Windows-компьютер, вариант 1 — планировщик задач** (без доп. программ). В PowerShell **от имени администратора**:
```
powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 -StartNow
```
Запускайте **в текущем окне PowerShell** (`cd` в папку бота, затем `.\scripts\install-autostart.ps1 -StartNow`), а не через
`powershell -File ...`: на части компьютеров политика запрещает запуск второго `powershell.exe` (ошибка
`ApplicationFailedException` / «Access is denied»). Если файл скачан архивом, один раз выполните `Unblock-File .\scripts\install-autostart.ps1`.
Если запрещены и скрипты PowerShell, можно использовать `scripts\run-bot.cmd` (ярлык в папке автозагрузки,
`Win+R` → `shell:startup`). Но на части компьютеров политика блокирует и запуск `.cmd`-файлов («нет нужных
разрешений»). Тогда создайте ярлык в `shell:startup` не на файл, а на `cmd.exe`:

- Объект (расположение):
  `C:\Windows\System32\cmd.exe /c "for /l %i in (1,0,2) do (node --use-system-ca --env-file=.env src/bot.js >> logs\bot.log 2>&1 & ping -n 11 127.0.0.1 >nul)"`
- Рабочая папка: `C:\eskhata\eskhata-release-bot` (папка `logs` должна существовать)
- Окно: свернутое

Бот будет стартовать при входе в Windows, перезапускаться через 10 секунд после падения и писать лог в `logs\bot.log`.

Бот стартует вместе с Windows (даже если никто не вошёл в систему) и перезапускается при падении; вывод пишется в
`logs\bot.log`. Без прав администратора бот стартует только при входе пользователя. Node.js должен быть установлен
для всех пользователей (не из профиля, как nvm). Удалить: `Unregister-ScheduledTask -TaskName ReleaseBot -Confirm:$false`.
Обновить бота: остановить задачу (`Stop-ScheduledTask -TaskName ReleaseBot`), заменить файлы, запустить снова.

**Windows-компьютер, вариант 2 — pm2:**
```
npm install -g pm2
pm2 start ecosystem.config.cjs
pm2 save
```
Автозапуск при старте Windows — через `pm2-windows-startup` (`npm i -g pm2-windows-startup`, затем `pm2-startup install`).

Состояние (`data/state.json`) пишется атомарно, а копия кладётся в `data/backup/` при старте и каждые 6 часов
(хранятся последние 14 дней).

## Добавить бота в ещё одну группу

1. Добавьте бота в группу (участники → Добавить → `@TestResultEskhata_bot`); для `/guide` дайте право закреплять сообщения.
2. В этой группе напишите `/myid` — бот ответит ID чата (вида `-100…`); команда работает даже в группе, не внесённой в список.
3. Добавьте ID в `.env` через запятую: `ALLOWED_CHAT_ID=-1004499457810,-100XXXXXXXXXX` и перезапустите бота.
   Если группа позже станет супергруппой (например, после выдачи админских прав), её ID изменится на `-100…` —
   тогда снова выполните `/myid` и замените ID в списке: со старым ID админские команды молчат.
4. В новой группе выполните `/guide`, проверьте `/testers` и запускайте `/release`.

Релизы, сводки, статистика и приветствия у каждой группы свои. Общие для всех групп: список тестировщиков
(`testers.json`), админы и личные напоминания. Если `ALLOWED_CHAT_ID` пуст, бот работает в любой группе.

## Как пользоваться (админ)

0. **Без команд:** просто вставьте/перешлите список в группу — бот сам найдёт задачи (от 2 ключей Jira) и под
   сообщением предложит кнопки «🚀 Создать релиз» / «⏰ Создать до 17:00» (`DEFAULT_DEADLINE` в `.env`). Работает
   только для админов и при выключенном privacy mode (BotFather → `/setprivacy` → Disable).
   После «можно выпускать» под сообщением появится кнопка **«🚀 Сервер переключен — объявить»**: командам уйдёт
   «Коллеги, сервер переключен…» с тегами тестировщиков, исключённые задачи не упоминаются. Если остались
   незакрытые задачи, бот предложит кнопки «Исключить их и объявить» / «Объявить как есть».
1. Либо классически: отправьте список релиза (секции вида `Название (N задач)` желательны, но не обязательны: если есть только строки `[BNPL-968] - описание`, бот сгруппирует задачи по проектам и сообщит об этом; если заявленное число задач не совпало с найденным — предупредит).
2. Ответьте на него `/release` или `/release до 17:00` (со сроком).
3. Бот пришлёт в группу сводку (прогресс по секциям, обновляется сама). Задачи с кнопками уйдут тестировщикам
   **в личку** (кто писал боту `/start`), а одним сообщением в группе бот отметит, кому ушло и кому нужно написать боту.
   Остальным задачи придут **отдельными сообщениями в группе** (тег один раз — в первой задаче).
   Вам лично бот пришлёт раскладку («у Daler — 5, без тестировщика — 2») с кнопками «✏️ Назначить» / «✏️ Переназначить».
4. Когда все ответили, бот пишет «можно выпускать» и присылает итоговый отчёт; кнопка «Сервер переключен — объявить»
   приходит админам в личку.
   Если есть непройденные — предупредит и будет ждать.
5. Дополнить релиз: вставьте новые задачи в группу и нажмите «➕ Добавить в текущий релиз» (или `/release add`); повторы по ключу пропускаются.

| Команда | Что делает |
|---|---|
| `/release [до ЧЧ:ММ]` | новый релиз из списка (ответом на сообщение или текстом после команды) |
| `/release add` | добавить ещё часть списка к текущему релизу; задачи, уже бывшие в релизе, пропускаются |
| `/deadline 17:00` / `off` | задать или снять срок |
| `/log` | последние 15 действий админов: кто создал релиз, назначил, исключил задачу, объявил, закрыл |
| `/panel` | панель кнопок: статус, кто отстаёт, напомнить всем, отчёт, срок (15/17/19 или снять), объявить, «✏️ Переназначить», закрыть релиз |
| `/who` | кто что не закрыл: тестировщики по убыванию открытых задач, сколько ждут; кнопки «🔔 имя» (напомнить одному) и «🔔 Напомнить всем». Без тегов — обзор никого не уведомляет |
| `/status` | прогресс по релизу |
| `/report` | итог: прошли / не требуют теста / не пройдены (с причинами) / без ответа / не готовы / исключены, со ссылками на вложения |
| `/export` / `/export all` | выгрузка в CSV (открывается в Excel): текущий или последний релиз / вся история |
| `/stats` | статистика: задачи и среднее время подтверждения по тестировщикам, доля отказов по командам |
| `/remind` | напомнить сейчас, не дожидаясь интервала |
| `/stop` | закрыть релиз |
| `/exclude SN-543 EA-12` | убрать задачи из релиза (или ответом на сообщение задачи в группе): их не ждём, не напоминаем, они не попадают в `/live`; вернуть можно кнопкой «↩️ Изменить» |
| `/live` | после выката: пишет «Коллеги, сервер переключен… задачи уже на боевой версии», тегает тестировщиков со ссылками на их задачи. Исключённые задачи не упоминаются. Если остались задачи без итога — предупредит и предложит кнопки «Исключить и объявить» / «Объявить как есть»; `/live force` отправит всё равно. Обычно хватает кнопки «Сервер переключен — объявить» под «можно выпускать» |
| `/assign SN-543 @user` или `/assign Лояльность @user` | назначить/переназначить тестировщика (в т.ч. для секции без владельца) |
| `/reload` | перечитать `testers.json` без перезапуска и назначить задачи, у которых не было тестировщика |
| `/addtester @user KEY1,KEY2 \| Секция 1; Секция 2` | добавить QA (или дополнить существующего) прямо из группы, без правки файла; сразу назначает задачи текущего релиза без тестировщика. Можно ответить командой на сообщение человека (`/addtester KEY1 \| Секция`) — подойдёт и тем, у кого нет username |
| `/removetester @user` | убрать QA из `testers.json`; бот предупредит, если у него остались открытые задачи |
| `/testers` | кто за какие секции отвечает |
| `/guide` | памятка для QA, закрепляется в группе |
| `/welcome` | предпросмотр приветствия, которое бот отправляет новым участникам |
| `/start` | в личке с ботом: включает личные задачи и напоминания; в группе — шпаргалка по командам |
| `/my` | (любой участник) ваши открытые задачи со ссылками на сообщения; в личном чате с ботом — по всем группам |
| `/find SN-561` / `/find кэшбэк` | (любой участник) в каких релизах была задача (по ключу или тексту): дата, тестировщик, итог, причина отказа. Показывает до 10 совпадений, новые сверху |
| `/myid` | ваш user id и id чата |

## Как работает QA

- Под задачей кнопки: **✅ Протестировано**, **❌ Не пройдена**, **➖ Не требует теста** и **🚧 Задача не готова**.
- После ✅ бот сам открывает поле ответа — остаётся прикрепить скриншот/видео и отправить.
  Только после вложения задача становится ✅. Можно отправить несколько файлов.
- Если у тестировщика несколько задач, в каждой указано «задача 2 из 3» (в группе тег ставится один раз — в первой). Подсказка «прикрепите файл» отвечает на сообщение своей задачи и называет её целиком
  (ключ и описание), а после вложения превращается в «✅ SN-561 — …, вложений: N» — так у файла всегда
  видна цитата, к какой задаче он относится. В сводке ключи задач в группе — ссылки на их сообщения (карточки в личке без ссылок).
- **Личка (чтобы лента группы была короче).** Если тестировщик один раз написал боту `/start`, его задачи
  с кнопками приходят ему лично, а в группе остаются список, сводка (одно обновляемое сообщение), итог и
  объявление; кого тегать и кому нужно написать боту, бот сообщает одним сообщением. Подсказки
  «прикрепите файл» и «напишите причину» тоже приходят в личку. Файл, отправленный боту, бот копирует
  в группу (с подписью задачи и автора) — доказательство видно всем, ссылки 📎 в отчёте работают.
  Отключить: `TASKS_IN_DM=false`. Ссылки на сами карточки в личке в группе не открываются. Если ждётся одна
  задача, указывать, к какой, не нужно; причину для ❌ в личке можно написать обычным текстом. Кто не писал
  боту `/start`, работает как раньше — подсказки в группе.
- ❌ — вложение не нужно; бот просит причину ответом и тегает автора списка.
- ➖ — для задач, которые нечем тестировать (например, backend без интерфейса).
- 🚧 — задача не выкачена или не готова к проверке: бот её не ждёт, не напоминает и не включает в сообщение «сервер переключен». Автору списка уходит сообщение в группу, а админам — личное с кнопкой «🚫 Исключить из релиза» (убрать задачу совсем). В отчёте такие задачи идут отдельным блоком «Не готовы». Вернуть — «↩️ Изменить».
- Ошиблись — «↩️ Изменить» у завершённой задачи. Завершённые задачи сжимаются до двух строк.
- Если QA отправил файл без Reply, а ждёт он ровно одну задачу — бот сам привяжет файл. Можно также
  написать номер задачи в подписи (`SN-543`). Иначе бот подскажет, что сделать.
  Важно: файлы без Reply Telegram доставляет боту только при выключенном privacy mode
  (BotFather → `/setprivacy` → Disable). Без этого работает путь «✅ → открывшийся ответ».

## Что бот присылает админам в личку

Если админ написал боту `/start`: кнопка «🚀 Сервер переключен — объявить» после «можно выпускать», утренняя сводка,
кнопка «🚫 Исключить из релиза» для задач, отмеченных 🚧, и служебные подсказки (опечатки в списке, «не найден
тестировщик для…»). Если лично доставить некому — всё приходит в группу.

После создания релиза (и после «Добавить в текущий») создатель получает личное сообщение с раскладкой: «Создано: 13 задач: у Daler — 5, у Amir — 3, без тестировщика — 2» и кнопками «✏️ Назначить» (только задачи без тестировщика) и «✏️ Переназначить» (все открытые). Те же кнопки доступны в `/panel`. Порядок: выбрать задачу → выбрать тестировщика из `testers.json` → готово, список остаётся открытым для следующей задачи. Новый тестировщик получает карточку, прежний — теряет её; для человека не из `testers.json` используйте `/assign KEY @user`.

**Итоги недели.** По понедельникам после `DIGEST_TIME` админам лично приходит статистика за последние 7 дней по всем группам (отключить: `WEEKLY_STATS=false`). Журнал действий хранится в `data/state.json` (последние 300 записей).

Эти сообщения по релизу получает **только админ, создавший релиз** (или совершивший действие), чтобы админы не
дублировали друг другу уведомления. Если ему не доставить (не писал боту `/start`), сообщение показывается в группе,
а другим админам не пересылается. Чтобы вернуть рассылку всем админам, поставьте `ADMIN_NOTIFY=all` в `.env`. Сообщения «бот жив» и
«бот снова работает» по-прежнему приходят всем админам. Кнопки «напомнить», «исключить» и «объявить» может нажать
любой админ, в том числе в `/panel` и `/who`.

Контроль до срока: в рабочее время **за 3 часа и за 1 час до срока** бот пишет админу «осталось N задач» с разбивкой
по тестировщикам и кнопками «🔔 напомнить» (раз на окно; смена срока сбрасывает предупреждения).

«Бот жив»: после простоя (больше 10 минут) при запуске бот пишет админам, сколько был недоступен; раз в рабочий день
в `HEARTBEAT_TIME` — «🟢 Бот работает» с числом открытых задач. Нет сообщения — повод проверить компьютер/бота.
Сам упавший бот написать не может, поэтому это именно сигнал по отсутствию.

## Напоминания и срок

- Раз в `REMIND_EVERY_MIN` минут, в рабочие часы, бот напоминает тем, кто не ответил.
  Если тестировщик написал боту `/start` в личные сообщения — напоминание придёт ему лично, иначе в группу.
- Утренняя сводка: по будням после `DIGEST_TIME` бот лично присылает админам прогресс по открытому релизу
  (админам нужно один раз написать боту `/start`; иначе сводка придёт в группу). В день создания релиза не шлётся.
- Если задан срок: за 3 часа напоминания каждые 30 минут, за час — каждые 15, а когда срок вышел,
  бот один раз тегает автора списка и `RM_USERNAMES` со списком незакрытого.

## Кто за что отвечает

**Новый QA:** добавьте его в группу (бот пришлёт приветствие), затем в группе выполните
`/addtester @username KEY1,KEY2 | Название секции` — вручную править файл не нужно. Уволился или сменил команду —
`/removetester @username`. Ключ проекта — префикс задач Jira (для `EJ-697` это `EJ`).

Файл `testers.json`: у каждого тестировщика `projects` (префикс задач Jira: SN, PTOPA, EJ…) и `titles`
(часть названия секции). Тестировщик определяется **по каждой задаче**: сначала по префиксу ключа
(`EJ-697` → проект EJ), и только если проекта нет в файле — по названию секции. Поэтому в секции вроде
«EO Admin and Integration» задачи разных команд уходят своим тестировщикам. После правки файла — `/reload`.
Пользователю без username укажите `"userId": 123456` вместо `"username"`.
Если один проект ведут несколько тестировщиков, задачи делятся поровну: каждая следующая уходит тому,
у кого сейчас меньше задач в этом релизе.
